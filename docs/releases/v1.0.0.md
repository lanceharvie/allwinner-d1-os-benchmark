# RunTime Panel v1.0.0 - Allwinner D1 OS Bring-Up, Benchmarks and Touch UI

RunTime Panel v1.0.0 consolidates a same-hardware comparison of Linux, RT-Thread RT-Smart, and Apache NuttX on the Sipeed Lichee RV / 86 Panel, together with the native touchscreen application developed after the benchmark work.

## Highlights

- Compared Linux, RT-Smart 5.0.2, and NuttX 13.0.1-RC0 on the same single-core Allwinner D1 / XuanTie C906 platform.
- Created and validated a local Apache NuttX D1 board port in FLAT S-mode.
- Stabilized RT-Smart D1 bring-up; the associated upstream work is tracked in [RT-Thread/rt-thread#11714](https://github.com/RT-Thread/rt-thread/pull/11714).
- Preserved protection-model differences and benchmark limitations rather than presenting the three environments as equivalent.
- Diagnosed an inherited approximately 16-second Allwinner watchdog left active by U-Boot.
- Diagnosed the tested SBI TIME path, where `set_timer` succeeded but supervisor timer pending was not delivered through STIP.
- Replaced that path with native Allwinner D1 Timer1 scheduling support.
- Corrected the Timer1 interval from 24,000 to 23,999, eliminating the effective 24,001-clock period and approximately 41.7 ppm drift.
- Validated that 115200-baud UART output perturbed the latency measurement; final timing intervals ran silently.
- Brought up the stable 720 x 720 display at approximately 58.1 fps using the `default_lcd` profile.
- Validated framebuffer color output, PWM7 backlight control, `fts_ts` capacitive touch, XR829 Wi-Fi, DNS, and Internet connectivity.
- Added the lightweight native RunTime system dashboard and interactive Home smart-home UI mockup.

## Headline result

The NuttX loaded 1 ms periodic test produced p50 0.542 us, p99 0.583 us, p99.9 0.708 us, maximum 0.708 us, and 0 missed periods out of 20,000. The phase-alignment midpoint uncertainty was approximately +/-0.375 us, so the supported conclusion is sub-microsecond wake-up behavior at the measurement floor with extremely tight tails.

These NuttX results are from a FLAT S-mode shared-address-space configuration without process isolation. They are not directly equivalent to Linux or RT-Smart protected-process costs.
